# TRADE//OS 指标字典

状态：阶段 0 草案；阶段 1 必须以真实数据对账  
版本：2026-07-28

## 1. 计算原则

1. 只使用用户确认后的结构化交易。
2. “已平仓”不等于“结果完整”；必须另行判断是否有已实现净盈亏。
3. 金额统计必须使用同一账户、同一基础货币。
4. 跨币种账户不能直接相加，除非存在明确汇率和换算时间。
5. 所有时间分组使用交易账户配置的 IANA 时区。
6. 数据不完整时返回 `null / 不可计算`，不能自动补零。
7. 页面标题使用简短名称；公式、条件和限制放入 Information。

## 2. Canonical Trade：标准交易记录

阶段 1 的标准交易至少需要：

| 字段 | 是否必需 | 说明 |
|---|---:|---|
| accountId | 是 | 必须属于当前用户 |
| source | 是 | CSV、SCREENSHOT、MANUAL |
| sourceTradeId | 优先 | 券商成交/订单标识；用于可靠去重 |
| symbol | 是 | 只来自用户记录；保留原值并另存标准化值 |
| direction | 是 | LONG / SHORT；无法识别时必须要求确认 |
| openedAt | 是 | 含原始时区或明确账户时区 |
| closedAt | 已平仓必需 | 缺失时不可计算持仓时长 |
| status | 是 | OPEN / CLOSED |
| grossRealizedPnl | 视来源 | 扣费前已实现盈亏 |
| commission | 可选 | 保留独立字段 |
| swapOrFinancing | 可选 | 保留独立字段 |
| otherFees | 可选 | 保留独立字段 |
| netRealizedPnl | 结果分析必需 | 必须能确认是否已含各类费用 |
| initialRiskAmount | R 分析必需 | 交易建立时的实际风险金额 |
| actualR | 可计算 | `netRealizedPnl / initialRiskAmount` |
| sourceTimezone | 是 | 原始记录解释时区 |
| accountTimezone | 是 | 用户分析和显示时区 |
| confirmedByUser | 是 | 提取数据必须确认后才能进入正式分析 |

当前数据库只有 `pnl` 和合并后的 `fees`，无法可靠判断 `pnl` 是否已经扣费，也无法区分 commission、swap 和其他费用。阶段 1 必须先解决这个数据模型问题。

## 3. 数据资格

### 已平仓交易

`status = CLOSED`

只表示交易已结束，不保证盈亏完整。

### 有结果交易

`status = CLOSED AND netRealizedPnl is known`

胜率、盈利因子、最佳/最差交易和累计净盈亏只使用有结果交易。

### R 完整交易

`有结果交易 AND initialRiskAmount > 0 AND actualR is known`

平均实际 R 和每笔期望（R）只使用 R 完整交易。

### P&L 完整度

`有结果交易数 / 已平仓交易数`

必须同时显示分子分母，例如 `47 / 50（94%）`。不足 100% 时应标明“盈亏不完整”。

## 4. 核心指标

### 已实现净盈亏

中文：已实现净盈亏  
英文：Net Realized P&L

公式：

`Σ netRealizedPnl`

条件：

- 只计算有结果交易。
- 不包括未实现盈亏。
- 若来源无法确认是否含费用，显示“费用口径待确认”，不能宣称“净”。

当前代码风险：

- `totalPnL` 直接累加 `pnl`。
- `totalFees` 单独累加，但未从 `totalPnL` 扣除。
- 注释假设来源可能已经含费，口径不统一。

### 胜率

中文：胜率  
英文：Win Rate

公式：

`盈利交易数 / 有结果交易数 × 100%`

规定：

- 盈亏为 0 的交易进入分母，但不进入盈利交易数。
- 必须同时显示样本，例如 `9 / 20`。
- 小样本只描述当前记录，不宣称稳定优势。

### 盈利因子

中文：盈利因子  
英文：Profit Factor

公式：

`盈利交易净盈利总额 / |亏损交易净亏损总额|`

显示规则：

- 没有亏损且存在盈利时可显示 `∞`，同时标明样本不足。
- 没有盈利也没有亏损时显示 `—`。
- 不称为“盈亏比”，避免与 Reward/Risk 混淆。

### 平均实际 R

中文：平均实际 R  
英文：Average Realized R

公式：

`Σ actualR / R 完整交易数`

规定：

- 不得用计划 R:R 替代。
- 无初始风险金额时不可从盈亏金额猜测。
- 必须显示 R 完整样本数。

### 每笔期望（R）

中文：每笔期望（R）  
英文：Expectancy per Trade (R)

首选公式：

`Σ actualR / R 完整交易数`

等价展开：

`胜率 × 平均盈利 R + 亏损率 × 平均亏损 R`

其中平均亏损 R 保留负号。Breakeven 的 R 为 0。

当前代码风险：

- 先使用胜率 × 平均盈利 R − 亏损率 × 平均亏损绝对值。
- 缺值时退化成平均 R，导致同一指标可能使用不同口径。
- 阶段 1 应统一为“实际 R 的算术平均”，不静默切换公式。

### 最大交易结果回撤

中文：最大交易结果回撤  
英文：Maximum Trade-Result Drawdown

公式：

1. 按 `closedAt` 排列有结果交易。
2. 从起始余额累计 `netRealizedPnl`。
3. 每点回撤 = 历史峰值 − 当前累计余额。
4. 最大值为最大回撤。

百分比：

`最大回撤发生时的金额 / 当时峰值余额 × 100%`

限制：

- 起始余额缺失时百分比不可计算。
- 存取款缺失时不能称为完整账户回撤。
- 当前代码按 `tradedAt` 排序，应在阶段 1 决定并统一为 `closedAt`。

### 累计已实现盈亏曲线

中文：累计已实现盈亏  
英文：Cumulative Realized P&L

公式：

按账户时区和 `closedAt` 分组，累计 `netRealizedPnl`。

限制：

- 没有起始余额时不能称为 Equity Curve。
- 当前代码使用 `tradedAt` 和 JavaScript UTC 日期分组，与账户时区不一致。

### 最佳/最差交易

公式：

- 最佳交易：`max(netRealizedPnl)`
- 最差交易：`min(netRealizedPnl)`

必须显示交易链接，不能只有数字。

### 连赢/连亏

按 `closedAt` 排列有结果交易：

- 盈利继续连赢，重置连亏。
- 亏损继续连亏，重置连赢。
- Breakeven 同时中断连赢和连亏。

当前代码让 Breakeven 不打断 streak，阶段 1 必须修正或明确采用不同定义。

## 5. 分组指标

分组可使用：

- 标的
- 多空方向
- 星期
- 小时段
- Session
- 持仓时长
- 账户
- 用户自定义字段（以后）

每个分组必须同时返回：

- 有结果交易数。
- 盈利/亏损/Breakeven 数。
- 胜率。
- 已实现净盈亏。
- 平均实际 R（若完整）。
- 数据完整度。
- 组成该结果的 trade IDs。

当前代码的 `trades` 数可能包含 OPEN 或没有 P&L 的记录，而胜率只使用有结果交易。UI 必须区分“记录数”和“有结果样本数”。

## 6. 星期 × 时段热力图

归属：

- 只在分析页展示完整矩阵。
- 首页只展示最佳/最差时段摘要。

计算：

- 使用 `openedAt` 判断用户选择交易的时间。
- 使用账户 IANA 时区计算星期和小时。
- 只用有结果交易决定胜率和净盈亏颜色。
- 记录数、样本数、胜率、总 R 和涉及标的必须可查看。

可靠度初始分级：

| 有结果样本 | 表达 |
|---:|---|
| 0–4 | 数据过少 |
| 5–9 | 仅供观察 |
| 10–29 | 初步模式 |
| 30–49 | 模式形成中 |
| ≥50 | 较强样本，但仍不代表未来 |

颜色不能由第一笔交易直接变成深绿/深红。阶段 3 应使用经过样本权重收缩的表现分数，并在 Information 中公开计算说明。

## 7. 禁止表达

- 缺失 P&L 时显示 `$0`。
- 缺失起始余额时显示 `0% 最大回撤`。
- 只有 1–2 笔时宣称“优势”“最佳时段”或“建议停止”。
- 把计划 R:R 与实际 R 混为一谈。
- 把确定性公式生成的文字称为“AI 引擎运行中”。
- 跨不同基础货币账户直接合计金额。
