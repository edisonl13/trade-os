# 阶段 1：真实数据验收样本清单

状态：待用户提供或授权使用脱敏样本  
版本：2026-07-28

## 1. 目标

证明 TRADE//OS 能把不同来源的真实交易记录，可靠转换为同一标准数据，并与原始来源逐笔对账。

没有通过本验收，不进入分析页重构。

## 2. 最少三组真实来源

### 样本 A：MT4 或 MT5

最低要求：

- 30–100 笔。
- 包含盈利、亏损和 Breakeven。
- 包含 commission、swap 或其他费用。
- 包含至少一笔跨日交易。
- 包含至少一笔仍未平仓记录（如果导出支持）。

### 样本 B：cTrader、IC Markets 或另一券商

最低要求：

- 30–100 笔。
- 列名和日期格式与样本 A 不同。
- 包含小数点位和不同手数。
- 包含券商符号后缀或前缀，例如 `EURUSD.a`、`OANDA:EURUSD`。

### 样本 C：FX Replay、OANDA 或其他回测导出

最低要求：

- 30–100 笔。
- 包含 realized P&L 或 R。
- 包含回测时区。
- 若同时存在 uPnL 和 rPnL，必须验证系统只使用正确字段。

如果当前拿不到三种来源，可以先用两种真实来源加一份人工构造边界样本，但不能把人工样本当作市场兼容性证明。

## 4. 必测边界案例

### 数据完整性

- 已平仓但 P&L 缺失。
- P&L 为 0。
- 费用为 0。
- 负 commission、正 rebate。
- swap 与 commission 分列。
- P&L 已含费用和未含费用两种来源。
- 缺失 close time。
- 缺失 stop loss，无法计算 R。

### 时间

- UTC、UTC+8 和带夏令时的 IANA 时区。
- 跨午夜交易。
- 跨夏令时切换日期。
- 开仓日和关仓日不同。
- CSV 只有本地时间但没有时区。

### 标的

- 外汇、指数、黄金、加密资产。
- 带 `/`、`.`、`-`、券商前缀/后缀的 symbol。
- 同一经济标的在不同券商的不同代码。
- 不得把市场上所有标的预置到下拉菜单；筛选项只从用户数据生成。

### 交易结构

- 同一订单多次部分平仓。
- 多次成交合并成一个头寸。
- 一笔交易多次加仓。
- 同一时间同一标的两笔独立交易。
- OPEN 与 CLOSED 混合。

### 导入行为

- 完全相同文件重复上传。
- 文件排序改变后再次上传。
- 文件名改变但内容相同。
- 同一交易出现在重叠日期导出中。
- 用户修改映射后重新导入。
- 无法识别方向时不得默认 LONG。

### 格式

- UTF-8、UTF-8 BOM。
- 逗号和分号分隔。
- 小数点 `.` 与小数逗号。
- 括号负数、货币符号、千位分隔。
- 空行、坏引号和额外标题行。

## 5. 对账闸门

每个真实样本都必须达到：

- 应导入交易数：100% 一致。
- 有结果交易数：100% 一致。
- 每笔 symbol、direction、openedAt、closedAt：100% 一致或明确要求用户修正。
- Gross、费用、Net：逐笔精确到来源精度。
- 总净盈亏：与来源一致。
- 重复上传：新增 0 笔。
- 不确定方向：0 笔被静默默认 LONG。
- 不确定时间：0 笔被静默使用当前时间。
- 缺失 P&L：0 笔被静默当作 `$0`。
- 账户隔离：用户 A 无法读取、修改或删除用户 B 数据。

任何一项未通过，阶段 1 不通过。

## 6. 产品体验验收

测试者必须能看见：

- 系统识别到的来源。
- 自动映射字段。
- 未映射字段。
- 每行错误和警告。
- 将被跳过的记录。
- 可能的重复交易。
- P&L 是否含费用的确认。
- 原始时区和账户显示时区。
- 保存前的汇总对账。

用户必须能够：

- 修改映射。
- 修改单行字段。
- 排除一行。
- 取消整个导入。
- 保存确认结果。
- 导出保存后的标准数据。
- 删除导入批次并恢复到导入前状态。

## 7. 脱敏规则

用户提供验收样本前：

- 删除姓名、邮箱、完整券商账号和地址。
- 可用稳定假名替换账号，但不能改变交易 ID、时间、金额和费用。
- 不上传 API Key、登录凭证或付款资料。
- 原始样本保存在项目外的受控目录；仓库只保存经过批准的脱敏 fixture。

## 8. 当前代码已知阻断风险

- CSV 去重键包含行号，文件排序改变可能绕过去重。
- 无法识别方向时默认 LONG。
- 无交易时间时可能使用当前时间。
- 多个费用列映射到同一个字段时可能只取一个非零值，而不是正确合计。
- OANDA 同时映射 uPnL 和 rPnL，需要严格优先 realized P&L。
- 当前 schema 无法表达 P&L 是否已含费。
- 截图保存按 UTC 推导星期和 Session，没有使用账户时区。
- 当前直接邮箱登录不适合多用户隔离验收。
